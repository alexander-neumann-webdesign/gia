## 2026-05-11 - BaseComponent Instantiation Optimization
**Learning:** Gia's `_autoBindFunctions` implementation traversed the prototype chain via `Object.getOwnPropertyNames` and checked `typeof this[method] === "function"` for *every single component instantiation*. Since `this[method]` accesses the instance (which resolves to the prototype), it executes any getters defined on the prototype. If a getter depends on uninitialized instance variables (like `this.element`), it throws a `TypeError` and crashes component instantiation.
**Action:** When caching component prototype methods using a `WeakMap`, ensure function checks are performed safely on the prototype object itself without triggering getters by using `typeof Object.getOwnPropertyDescriptor(proto, method)?.value === "function"`. Additionally, when iterating over external state objects in performance-critical paths like `setState`, prefer standard `for` loops with `Object.keys()` over `for...in` to avoid accidentally iterating over inherited enumerable properties.
## 2024-02-12 - [O(N) to O(K) in MutationObserver auto-mounting] **Learning:** Found a specific bottleneck in Gia's `autoMountComponents` feature. The `MutationObserver` fired on newly added nodes, but instead of traversing only the added subtrees to initialize components, it called `loadComponents` on the entire `document.body`. This resulted in an O(N) full DOM traversal (where N is total nodes in the document) on every single mutation, causing main thread blocking and lag on larger pages when DOM nodes were incrementally appended. **Action:** Refactored the `MutationObserver` callback to collect `addedNodes` and run the initialization traversal *only* on those added elements. This transforms the operation from O(N) to O(K) (where K is the number of injected nodes). When building framework-level auto-mount observers, always localize the component search to the mutated subtrees.

## 2024-05-11 - Add aria-expanded to OffCanvasMenu toggle
**Learning:** For overlay components like modals or off-canvas menus, standard components might add the click listener but fail to initialize ARIA attributes or track the component state back to the UI element triggering it.
**Action:** When adding or updating toggling UI elements in this repo, ensure `aria-controls` is set connecting the button to the menu and that `aria-expanded` is dynamically updated when the component state changes.
## 2024-05-12 - Add aria-expanded and aria-controls to Modal toggle
**Learning:** Similar to off-canvas menus, modal dialog components with dynamic external triggers often lack the necessary ARIA attributes to connect the trigger button to the modal content (`aria-controls`) and to accurately broadcast the state of the dialog to screen readers (`aria-expanded`).
**Action:** Always ensure that dynamically attached external UI triggers for modals correctly initialize and continuously sync their `aria-controls` and `aria-expanded` attributes with the component's internal state.
## 2026-05-12 - Stack tab panels for smooth transitions
**Learning:** When fading out an active tab and fading in a new tab simultaneously, not stacking them causes layout shifts where both are temporarily visible in flow.
**Action:** Wrap tab panels in a container and use `display: grid` with overlapping children (e.g., `grid-area: 1 / 1`) to ensure stable crossfade animations.
## 2024-05-18 - Accordion UX/A11y Fixes
**Learning:** For `<details>` and `<summary>` based Accordion components using `interpolate-size: allow-keywords` for CSS `height: auto` transitions, the `:root` selector must be global. If it is nested inside a component selector within `@supports`, the `interpolate-size` property may not be correctly applied to the document root in some preprocessors or CSS OM parsers. Also, the `[open]` transition trigger must be placed outside the `@supports` block to ensure `height: auto` acts as a fallback for browsers that don't support `interpolate-size`, otherwise the content will have `height: 0` and remain invisible even when opened in older browsers. Summaries should also have `user-select: none` to prevent awkward highlighting on double click or dragging.
**Action:** Fixed SCSS nesting of `:root` within `@supports (interpolate-size: allow-keywords)`, ensuring it acts globally. Moved `[open]` selector to ensure fallback functionality, and added `user-select: none` to the summary element.

## 2024-05-12 - SEO & Accessible Scroll Reveals
**Learning:** Using purely `opacity: 0` for scroll-reveal components hides content from search engines (which might not trigger JS scroll observers) and can cause screen readers to read invisible content out of order. Additionally, elements with `opacity: 0` still intercept pointer events unless explicitly disabled.
**Action:** Implemented a `<noscript>` block to enforce `opacity: 1 !important` and `visibility: visible !important` as a fallback for crawlers and users without JS. Updated default CSS state to include `visibility: hidden` (alongside `opacity: 0`) with a transition delay on hide to ensure content is fully hidden from screen readers and pointer events until JS reveals it.
**Update (Correction):** Using `visibility: hidden` removes the element from the keyboard focus tree. This breaks the ability for keyboard-only users to `Tab` to links inside the unrevealed elements, preventing the browser from auto-scrolling to them, which in turn prevents the `IntersectionObserver` from ever revealing them. Instead of `visibility: hidden`, rely on `opacity: 0` alongside `pointer-events: none` to keep the elements focusable via keyboard while preventing accidental mouse interactions. Restore `pointer-events: auto` upon reveal.
## 2024-05-18 - Prevent layout shift in stateful buttons
**Learning:** Buttons that change text on click (like a "Copy" button changing to "Copied!") can cause jarring layout shifts as their width recalculates. Using a magic number `min-width` is brittle and doesn't scale with localization or dynamic content.
**Action:** Use a CSS grid stacking trick. Wrap the dynamic text and hidden "sizer" spans (containing all possible text variations with `aria-hidden="true"`) inside a container with `display: grid; grid-template-columns: 1fr;`. Apply `grid-row-start: 1; grid-column-start: 1;` to all children. The largest sizer will naturally dictate the container's width, preventing layout shift without hardcoded dimensions. Ensure an `aria-label` is applied dynamically to broadcast the state change to screen readers if the visual text does not change.
## 2026-05-13 - details/summary smooth height transition fix
**Learning:** When using `interpolate-size: allow-keywords` to smoothly transition native `<details>` elements from `height: 0` to `height: auto` using `::details-content`, it is not enough to just apply the transition properties. The `::details-content` pseudo element must explicitly be set to `display: block`. Furthermore, `display` must be included in the transition property with the `allow-discrete` keyword to make the box model correctly track the animation state.
**Action:** Added `display: block` to the `::details-content` rule and updated its transition string to `transition: height 0.5s ease, display 0.5s ease allow-discrete, content-visibility 0.5s ease allow-discrete;` in `demo.scss` and `Accordion.js`.
## 2026-05-12 - Add ARIA labels to Slider navigation buttons
**Learning:** Slider components often use brief text like "Prev" or "Next" for navigation buttons, which might eventually be replaced by icon-only designs in real-world usage. Without proper `aria-label`s, the context for screen readers can be ambiguous or completely lost if icons are used.
**Action:** Always ensure that generic slider navigation controls (like "Prev" and "Next") include descriptive `aria-label` attributes (e.g., "Previous slide") to provide unambiguous context for screen reader users.

## 2025-02-15 - Tabs component playful transition
**Learning:** SASS nesting view-transition pseudo-elements like `::view-transition-group(*)` inside a parent selector breaks them, as they are pseudo-elements of the `:root` document and will not match any elements if prefixed with a parent class. Furthermore, to apply transitions correctly to elements entering and leaving the DOM under the View Transitions API, the `viewTransitionName` must be given to BOTH the entering and exiting elements individually. Otherwise, the old element transitions implicitly as part of its container, leading to disjointed crossfades (e.g. smooth fadeOut but abrupt fadeIn).
**Action:** Moved view transition styles out of the `FilterableList` component in `demo.scss` to the global scope. Assigned unique `viewTransitionName` strings to both the `activePanel` (entering) and `oldPanel` (exiting) in `Tabs.js` so they correctly match the global `::view-transition-new(*):only-child` and `::view-transition-old(*):only-child` styles. Added a missing closing brace in `demo.scss` to fix compilation.
